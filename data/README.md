# Data

Readings from real avocados. This is how a good ripeness threshold gets found, so contributions are very welcome. The record format, why readings from different builds are comparable, and what pooled data is for are in [`../docs/data-sharing.md`](../docs/data-sharing.md).

## Contributing readings

1. On your device's page, **Download CSV** (that's `/data.csv?fruit=all&old=1`).
2. Put the file in `contrib/<your device id>/` (the id is on the page footer, e.g. `a3f9c2`). Any file name ending in `.csv`; one file per download is fine, duplicates are dropped on merge.
3. Open a pull request. The `data` workflow validates the file (schema v1 header, ids, timestamps, vocabularies) and says exactly what's wrong if anything is. Once merged, `all.csv` is rebuilt automatically.

Rows with a `human_rating` and no measurement are ratings you tapped; they are the labels everything else is trained against, so the **Perfect** tap matters more than any reading.

Nothing personal is in the file: a random device id, UTC timestamps, numbers.

## Files

| Path | What |
|---|---|
| `contrib/<device_id>/*.csv` | Raw contributions, as downloaded from devices |
| `all.csv` | Everything merged, sorted by device, fruit, time. Rebuilt by CI; don't edit |
| `sample/sample.csv` | **Synthetic**, from `tools/make_sample.py`, device id `000000`. For trying the dashboard and the scripts. Never merged |
| `readings_template.csv` | Column header, for hand-entered readings |

## Format (schema v1)

| Column | Meaning |
|---|---|
| `schema` | `1` |
| `device_id` | 6 hex chars, random, generated by the firmware on first boot |
| `fw_version`, `hw_version` | e.g. `0.1.0`, `v1` |
| `timestamp` | ISO 8601 UTC, `2026-11-09T07:30:12Z`; blank if the device had no clock |
| `fruit_id` | `<device_id>-<counter>`; new id when the firmware detects a swap or you tap *New avocado* |
| `variety` | e.g. `hass` |
| `fruit_mass_g`, `room_temp_c` | Optional |
| `contact_pos_mm` | Where the pad first touched, from the end stop |
| `stiffness_n_per_mm` | Slope of force vs. squish, blade bend removed. **The number.** Blank on rating rows |
| `squish_at_cap_mm` | Squish when the force cap was reached |
| `force_cap_n` | The cap used |
| `blade_k_n_per_mm` | That unit's blade spring (from its calibration) |
| `cal_points` | `grams:counts;…` from the coin calibration, so a bad calibration can be spotted |
| `curve` | `squish:force;…`, up to 24 points |
| `human_rating` | `hard`, `firm`, `ready`, `perfect`, `overripe` |
| `cut_open` | `no_bruise`, `bruise_at_pad`, `bruise_elsewhere` |
| `notes` | Free text |

Tools: `python3 tools/merge_data.py --check` validates locally; without `--check` it also writes `all.csv`.
